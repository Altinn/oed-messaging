# oed-messaging

Libraries wrapping Altinn 3 correspondence, used for messaging heirs in Digitalt dødsbo.

## Packages

| Package | Contents |
| --- | --- |
| [`Altinn.Dd.Correspondence`](Altinn.Dd.Correspondence/README.md) | Sending, searching and retrieving Altinn 3 correspondence. |
| [`Altinn.Dd.InternalEvents`](Altinn.Dd.InternalEvents/README.md) | Estate event types and resource ids shared across the programme. |

Both are published to nuget.org by the `Release Correspondence Package` and
`Release InternalEvents Package` workflows.

## Usage

Add the package `Altinn.Dd.Correspondence` from nuget.org and register the service in the DI
container. See [the package README](Altinn.Dd.Correspondence/README.md) for configuration, the
full service contract, and a migration guide from the retired `Altinn.Oed.Messaging` package.

`SendDdCorrespondence` is a console application for sending a correspondence by hand. To use it,
copy `SendDdCorrespondence/appsettings.json.template` to `appsettings.json` and populate it.

## Quality gates

`QaTests` holds two opt-in gates, both run nightly by `.github/workflows/qa.yaml`:

- **SonarGate** — a SonarQube quality gate over `Altinn.Dd.Correspondence`. Needs Docker.
  `Altinn.Dd.InternalEvents` is not scanned; add a second SonarGate test with its own project key
  to put it on the dashboard.
- **DependencyGate** — audits every project in the repo and fails on any advisory at High or
  above, matching the `WarningsAsErrors=NU1903;NU1904` in `Directory.Build.props` so the nightly
  gate and the build agree. Moderate and low are recorded without failing.

Both are skipped unless `QATESTS` is set:

```powershell
$env:QATESTS = "1"; dotnet test ./QaTests/QaTests.csproj
```

The runners live in the `Altinn.Dd.Tests.SonarGate` and `Altinn.Dd.Tests.DependencyGate` packages;
the test files here are just the option blobs. Package source:
<https://altinn.studio/repos/digdir/dd-qa>.

## Build-enforced conventions

`Directory.Build.props` turns on the XML documentation file and the IDE analysers for every
project, and `.editorconfig` raises one rule. Two things therefore fail the build rather than
drifting:

- **Unused `using` directives** (`IDE0005`), everywhere. The generated API client is exempt via its
  `<auto-generated>` header.
- **Undocumented public members** (`CS1591`) in the two published libraries, so
  `Altinn.Dd.Correspondence` and `Altinn.Dd.InternalEvents` ship complete IntelliSense. The test
  and sample projects generate the doc file only to enable `IDE0005`, and mute `CS1591`.

## Tests

`Altinn.Dd.Correspondence.Tests` covers the library — see
[its README](Altinn.Dd.Correspondence.Tests/README.md) for the layout. It needs no credentials and
makes no network calls:

```bash
dotnet test Altinn.Dd.Correspondence.Tests
```
